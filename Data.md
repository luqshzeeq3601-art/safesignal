# SafeSignal — Data Models

## Alert message (JSON, `protocolVersion` 1)

```json
{
  "protocolVersion": 1,
  "alertId": "3f1c9c0e-6c1e-4f0e-9d53-0a6c5b1f2e77",
  "workerId": "W-1042",
  "deviceId": "EMULATOR34X1X2X0",
  "type": "FALL",
  "raisedAtEpochMs": 1791878400000,
  "location": { "lat": 3.1390, "lon": 101.6869, "accuracyM": 5.0, "fixAtEpochMs": 1791878398000 },
  "batteryPercent": 87,
  "attempt": 1
}
```

- `type`: `FALL | MAN_DOWN | SOS`.
- `location` may be `null` (no fix within 5 s).
- `alertId` is a client-generated UUID, so a retried POST is idempotent.

## Server API

| Method | Path | Result |
|---|---|---|
| POST | `/api/alerts` | 201 new, 200 duplicate `alertId`, 400 invalid |
| GET | `/api/alerts` | all `AlertRecord`s, newest first (console polls every 2 s) |
| GET | `/api/alerts/{id}` | one `AlertRecord` (app polls for ack every 3 s) |
| POST | `/api/alerts/{id}/ack` | body `{"dispatcher":"D-1"}` → 200 |
| GET | `/health` | `OK` |
| GET | `/` | dispatcher console (static HTML + vanilla JS) |

`AlertRecord` = `{ alert, status: RECEIVED|ACKNOWLEDGED, receivedAtEpochMs, acknowledgedAtEpochMs?, acknowledgedBy? }`

Server store: in-memory map plus an append-only `alerts.jsonl`.

## Room table `alerts` (local history and outbox)

| Column | Type | Note |
|---|---|---|
| `alertId` | TEXT PK | UUID |
| `type` | TEXT | FALL / MAN_DOWN / SOS |
| `raisedAtEpochMs` | INTEGER | |
| `lat`, `lon`, `accuracyM` | REAL NULL | |
| `batteryPercent` | INTEGER | |
| `status` | TEXT | CANCELLED / PENDING / SENT / ACKNOWLEDGED |
| `attempts` | INTEGER | |
| `sentAtEpochMs`, `acknowledgedAtEpochMs` | INTEGER NULL | |
| `acknowledgedBy` | TEXT NULL | |

Rows with `status = PENDING` are the outbox that `AlertSyncer` retries.

## Relationships

```
AlertMessage (wire) ──1:1──► AlertRecord (server)      keyed by alertId
AlertMessage (wire) ──1:1──► alerts row (app, Room)    keyed by alertId
KPI events ──many:1──► alert                            keyed by alertId
```

## KPI CSVs

| File | Columns | Events |
|---|---|---|
| App `kpi_events.csv` | `epochMs,elapsedMs,alertId,event,detail` | `DETECTED, COUNTDOWN_CANCELLED, RAISED, SEND_ATTEMPT, DELIVERED, ACK_SEEN` |
| Server `server_events.csv` | `epochMs,alertId,workerId,event` | `RECEIVED, DUPLICATE, ACKED` |
| `battery.csv` | written by the KPI script from `dumpsys batterystats` | |

| KPI | Definition |
|---|---|
| Detection-to-alert latency | `DELIVERED − RAISED` (p50, p95); `RAISED − DETECTED` reported separately because it is the configurable countdown |
| Delivery success rate | alerts `DELIVERED` within 60 s of `RAISED` ÷ alerts `RAISED`; first-attempt rate also shown |
| False-alarm rate | `COUNTDOWN_CANCELLED ÷ DETECTED` (field); detector false positives on labelled non-fall traces (lab) |
| Battery use per hour | batterystats estimated mAh for the app uid ÷ run hours (emulator figures are estimates) |

## Sensor trace CSV (`detection/src/test/resources/traces/`)

`tMs,x,y,z` in m/s². File name prefix is the label: `fall_`, `walk_`, `sit_`, `drop_phone_`. Traces are synthetic, generated by `scripts/gen-traces.ps1`.
